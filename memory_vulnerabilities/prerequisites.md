# Prerequisite self-test: systems background

> Source: [10-question ungraded self-test](https://compsec.kisp-lab.org/Memory-Safety-Webbook/prerequisite-self-test.dc.html) and its [question/answer data](https://compsec.kisp-lab.org/Memory-Safety-Webbook/prereq-data.js). Covers all ten answers; use the live self-test to practice without spoilers.

- Q1 `/proc/<pid>/maps`: permissions `r-xp` executable code, `rw-p` writable data/heap/stack, `r--p` read-only data; identify by both filename and mapping label, not permissions alone. In supplied `/bin/cat` map: code base `0x00400000`, writable data base `0x0060b000`, `[stack]` base `0x7fff3b99d000`. Mappings show address range, permissions, file offset, device, inode, pathname.
- Q2–4, Q10 build pipeline: source → compiler → assembly → assembler → object → linker → executable → loader → process/memory map. At execution/startup the loader and executable are needed, not the compiler/assembler/linker. The quiz labels loader output “None” among the given *code-artifact* choices; in reality it loads/maps the process.
- Q5 dynamic `int **x` for 100 × 50: allocate 100 pointers, then each row of 50 integers; `x = malloc(100 * sizeof *x); for (int i=0;i<100;i++) x[i]=malloc(50 * sizeof *x[i]);` permits `x[i][j]`; check allocation failures and free each row and `x`. A flat 100×50 `int` allocation cannot be used as an `int **` (and allocating only `100*sizeof(int)` underallocates pointer array). Alternative: contiguous allocation with a suitable pointer-to-array type; quiz intentionally tests older row-by-row pattern.
- Q6 x86 call (quiz sequence `adgce`): place arguments → `call` pushes return address and jumps → prologue saves old frame pointer → set frame pointer to stack pointer. Linux i386 passes arguments on stack; x86-64 System V generally puts first six integer/pointer arguments in `rdi,rsi,rdx,rcx,r8,r9`. See [calling conventions](https://wiki.osdev.org/Calling_Conventions).
- Q7 return (quiz `eabc`): save return value → restore stack pointer from frame pointer → restore old frame pointer → `ret` pops saved return address into instruction pointer. Optimized builds can omit the frame pointer.
- Q8 `scanf("%d", ...)`: needs pointer to `int`. Given `int a, *b, c[1]; b=malloc(sizeof(int));`: `a` invalid; `b` valid; `c` valid (decays to `&c[0]`); `&a` valid; `&b` wrong type (`int **`); `&c` wrong type (`int (*)[1]`, despite often same numeric address). Quiz choices: `c,a,a,a,c,c`; wrong types are undefined behavior, not necessarily immediate faults. Allocation success is assumed by question; real code checks `malloc` and releases it.
- Q9: access outside mapped virtual memory (e.g. `0x5000000` when only `0x6000000–0x8000000` is mapped) → CPU page fault, control enters kernel; kernel may subsequently send SIGSEGV/kill process, not CPU directly.
